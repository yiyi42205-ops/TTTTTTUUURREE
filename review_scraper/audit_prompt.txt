# 特徵欄位說明
- username: 評論者名稱
- text: 評論內文
- stars: 評分星等（皆為高風險的五星）
- daysElapsed: 該評論發表距今的天數。注意：如果多個高風險評論的 daysElapsed 數值非常接近（例如都在相近的天數，如 5 天前、30 天前），代表它們在同一個時間點集中出現，具有極高的群體刷評或集中打卡活動嫌疑。
- isSpikePeriod: 布林值。若為 true，代表該評論是在評論發表密度異常暴增的「高峰期」所寫下。這通常強烈暗示了店家在該時段有集中的打卡送禮行銷活動或刷單行為。
- maxSimilarity: 0 到 1 之間的浮點數，代表本則評論與店內其他評論的最高文字結構相似度（3-gram Jaccard）。數值僅供參考交叉比對，並非直接判定依據——真實顧客描述同一道菜也可能有一定相似度。
- similarCount: 本則評論與店內其他評論結構相似（達到相似度門檻）的則數。數值越高，代表這則評論不是單一巧合，而是有一群結構相近的評論。
- hotTermCount: 本則評論命中「全店五星評論高頻詞組」（例如反覆出現的招牌菜名）的數量。
- hotTermMaxRatio: 本則評論命中的熱門詞組中，該詞組在全店五星評論中的最高出現占比（0 到 1）。占比越高，代表這個詞組（通常是招牌品項）被越多評論反覆提及。
- nearbyLongReviewCount: 本則評論發布時間前後 30 分鐘內，店內其他「長評」（字數 > 50 字）的則數。數值越高，代表疑似有多篇長文被集中批次貼出。

# 語意審查三維度評分 (1-5分)
對於每一則評論，你必須客觀給出以下三個維度的評分：
1. "incentiveIntensity" (利益誘因強度, 1-5分):
   - 5分：極度強烈。明文提及「打卡送小菜/甜點/折扣」，或文風完全屬於為了獲得贈品而寫的敷衍客套話。
   - 3分：中度懷疑。文風異常，高度吻合打卡活動的常用推薦句型。
   - 1分：無任何利益交換跡象。
2. "sentimentAuthenticity" (情感真實度, 1-5分):
   - 5分：極高。真情實感，有情緒起伏或具體的用餐心情分享。
   - 3分：中等。平鋪直敘。
   - 1-2分：極低。假惺惺、敷衍、像複製貼上的機器人模板，或是毫無靈魂的敷衍。對於極短且內容空洞的好評（如「好吃，讚！」、「好吃啦麵，讚！」），情感真實度應評為 2 或 1。
3. "descriptionGranularity" (描述細緻度, 1-5分):
   - 5分：極高。提及具體菜單品項（例如：黑蒜油豚骨拉麵、溏心蛋）、口感細節（麵條硬度、湯頭鹹度）、排隊時間、店內環境或服務細節。
   - 1-2分：極低。空洞無物（例如：「好吃讚！」、「拉麵好吃推薦」、「通化街拉麵好讚！」、「CP值高，老闆親切」等萬用套話）。

# 洗評判定規則
若符合以下任一條件，必須判定該評論為洗評 ("isWashed": true)：

1. 【利益交換洗評】：
   - incentiveIntensity >= 3（有利益傾向） 且 descriptionGranularity <= 2（描述空洞）。
   - 或者：評論內文明文提到打卡、送禮、優惠、打折、五星送小菜等關鍵字。
2. 【空洞模板洗評】(針對萬用短評)：
   - 評論字數短、內容空泛，缺乏任何與該店家相關的具體品項或消費細節。
   - 即使沒有提及利益交換字眼，若 descriptionGranularity <= 2 且 sentimentAuthenticity <= 2（例如：「好吃啦麵，讚！」、「美味推薦」、「環境乾淨好吃」），亦屬於低價值洗評。
   - 若 isSpikePeriod: true（集中發表期），對於這類空洞好評的判定標準應更嚴格，只要描述細緻度 <= 2 即可判定為洗評。
   - 注意：評論「字數短」本身不等於洗評。若短評中包含具體、可驗證的對象描述（例如提及「老闆」、「店員」等特定人物的互動、特定餐點名稱、特定場景細節），即使只有短短一句，也應給予較高的 descriptionGranularity（3分以上），不得僅因字數少就一律判定為空洞模板（詳見範例 D）。
3. 【情感虛假洗評】：
   - 情感真實度極低（sentimentAuthenticity <= 2），充滿機器人罐頭文感或與一般人消費心態不符。
4. 【結構同質模板洗評】(不以時間群聚為觸發前提——發文時間可相距數週甚至數月)：
   - 排程式代寫最常見的規避手法，就是刻意將同一份文案模板分散在不同時間點發布，藉此規避「集中發表期」偵測。因此本規則的觸發條件「不得」要求 isSpikePeriod 為 true 或 daysElapsed 彼此接近——即使兩則評論相隔數週、非集中發表期，只要結構同質即應觸發。
   - 若符合以下任一情形，無論 descriptionGranularity 多高、無論 daysElapsed 相距多遠，皆應整體判定為洗評（"isWashed": true，issueType 用 "template"，verdictBasis 用 "structural"）：
     a. 該評論與店內其他評論的 maxSimilarity 達 45% 以上，或 similarCount >= 1——即同店存在兩則以上結構高度同質的評論（例如開場句式雷同、招牌品項組合雷同、收尾句式雷同），無論這些評論的發文時間是否集中。
     b. hotTermCount >= 2 且 hotTermMaxRatio 偏高（例如 >= 0.3），代表評論反覆點名同一組招牌品項，且這些品項在全店五星評論中也被大量反覆提及，疑似套用固定行銷文案素材。此條件同樣與 isSpikePeriod 無關。
   - isSpikePeriod 為 true、daysElapsed 彼此接近、nearbyLongReviewCount 偏高，皆屬「加重訊號」：若同時符合上述任一結構同質條件，這些時間訊號應寫入 reasoningPath 以提高判定確定性，但絕不可作為觸發本規則的必要條件，也不可因為時間分散（isSpikePeriod: false、daysElapsed 相距很遠）就排除本規則的適用（見範例 F）。
   - 過去版本要求「descriptionGranularity <= 3」才觸發本規則，此條件已移除：專業代寫的行銷長評往往描述細緻、情感豐富，反而更容易被本規則放過，但這正是需要攔截的對象（見下方反向提醒）。

⚠️ 反向提醒：「描述細緻」不等於「真實」。專業代寫評論的特徵正是細節豐富、情感生動，但因套用同一份文案或簡報素材，會與店內其他評論呈現高度同質化（相似的招牌品項描述、相似的行文結構）——這種同質化不需要集中發表也會存在，切勿因為時間分散就放鬆警覺。請勿僅因 descriptionGranularity 高分就排除洗評可能性，務必交叉比對 maxSimilarity、similarCount、hotTermCount、hotTermMaxRatio 等結構性訊號，且這些訊號的判定不應以 isSpikePeriod 或 daysElapsed 相近為前提。

※ 若不符合上述任何洗評特徵，且有具體消費細節者，始得判定為真實評論 ("isWashed": false)。

# 判定範例 (Few-Shot Examples)
- 範例 A（利益交換洗評）：「打卡送奶酪！雞湯拉麵很好吃！」
  - 評分：incentiveIntensity: 5, sentimentAuthenticity: 2, descriptionGranularity: 2
  - 判定：isWashed: true | issueType: "incentive" | verdictBasis: "content" | reason: 提及打卡送奶酪，屬於典型利益交換。
- 範例 B（空洞模板洗評）：「好吃啦麵，讚！」 或 「美味拉麵推薦！」
  - 評分：incentiveIntensity: 2, sentimentAuthenticity: 2, descriptionGranularity: 1
  - 判定: isWashed: true | issueType: "template" | verdictBasis: "content" | reason: 字數極短且無任何具體餐點或消費細節，屬空洞模板。
- 範例 C（真實消費評論）：「今天跟朋友來吃，點了豚骨拉麵麵硬湯濃，叉燒有火烤香氣很讚！不過排隊等了快半小時，店內座位比較少。」
  - 評分：incentiveIntensity: 1, sentimentAuthenticity: 5, descriptionGranularity: 5
  - 判定: isWashed: false | issueType: "none" | verdictBasis: "content" | reason: 提及餐點細節、口感與排隊等真實體驗，屬真實評論。
- 範例 D（短評但真實）：「好吃　老闆很親切　推薦」
  - 評分：incentiveIntensity: 1, sentimentAuthenticity: 4, descriptionGranularity: 3
  - 判定: isWashed: false | issueType: "none" | verdictBasis: "content" | reason: 雖然字數短，但具體提及「老闆很親切」這類可驗證的人物互動細節，並非萬用套話，不應僅因簡短就判定為洗評。
- 範例 E（高細節模板洗評 / 代寫長評，集中發表期）：「一走進店裡就被撲鼻而來的湯頭香氣驚艷到了😍，招牌黑蒜油豚骨拉麵湯頭濃郁順口，叉燒軟嫩入味，配上溏心蛋根本絕配！服務也很親切，整體用餐體驗非常滿分，下次一定會再來 (´▽`)」
  - 評分：incentiveIntensity: 1, sentimentAuthenticity: 4, descriptionGranularity: 5
  - 特徵：isSpikePeriod: true, maxSimilarity: 0.62, similarCount: 4, hotTermCount: 2, hotTermMaxRatio: 0.55
  - 判定: isWashed: true | issueType: "template" | verdictBasis: "structural" | reason: 雖描述細緻、情感豐富，但與店內其他評論結構高度相似（maxSimilarity 62%、similarCount 4 則），反覆點名同一招牌菜「黑蒜油豚骨拉麵」（hotTermMaxRatio 55%）。isSpikePeriod 為 true 是加重訊號，但觸發判定的根本原因是結構同質，非集中發表本身。descriptionGranularity 高分不能排除洗評可能性。
- 範例 F（結構同質模板洗評 / 排程式代寫，發文時間分散、非集中發表）：同店兩則評論，發文時間相距 20 天：
  評論①（daysElapsed: 20）：「一走進門就被熱情招呼，主廚特製有機蝦鮮甜彈牙，黑鑽蜆湯濃郁鮮美，三品海鮮匯份量十足，CP值爆表，全家都愛，強力推薦！」
  評論②（daysElapsed: 0）：「服務態度真的很好，主廚特製有機蝦鮮甜彈牙，黑鑽蜆湯濃郁鮮美，三品海鮮匯份量十足，物超所值，全家都愛，大力推薦！」
  - 評分（以評論②為例）：incentiveIntensity: 1, sentimentAuthenticity: 4, descriptionGranularity: 5
  - 特徵：isSpikePeriod: false（兩則評論分屬不同月份，未達集中發表期門檻），maxSimilarity: 0.58, similarCount: 1, hotTermCount: 3, hotTermMaxRatio: 0.4
  - 判定: isWashed: true | issueType: "template" | verdictBasis: "structural" | reason: 兩則評論開場句式雷同、招牌品項組合「有機蝦／黑鑽蜆湯／三品海鮮匯」完全一致、收尾句式雷同，儘管發文時間相距 20 天且 isSpikePeriod 為 false（非集中發表期），仍屬排程式代寫模板，不因發文時間分散而排除洗評判定。

※ 範例 B 與範例 D 的關鍵差異：範例 B 完全沒有提及任何具體對象（人物、餐點、場景），純粹是空泛的形容詞堆疊；範例 D 雖然同樣簡短，卻點名了「老闆」這個具體互動對象。判定短評時，請以「是否有可驗證的具體對象」為準，而非單純以字數長短作為洗評依據。

※ 範例 C 與範例 E 的關鍵差異：兩者 descriptionGranularity 皆高分，但範例 C 的 maxSimilarity / similarCount / hotTermMaxRatio 皆低（獨特、非重複描述），範例 E 則在結構相似度與熱門詞組占比上都偏高。判定長評時，請勿只看描述細緻度，務必交叉比對這些結構性重複訊號。

※ 範例 E 與範例 F 的關鍵差異：範例 E 恰好處於集中發表期（isSpikePeriod: true），範例 F 則刻意分散發文、非集中發表期（isSpikePeriod: false）——但兩者觸發洗評判定的根本依據都是結構同質性（maxSimilarity/similarCount/hotTermMaxRatio），與 isSpikePeriod 無關。isSpikePeriod 只是加重訊號，其為 false 絕不代表可以排除結構同質模板洗評。
