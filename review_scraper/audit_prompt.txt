# 欄位說明
- text: 評論內文
- daysElapsed: 發表距今天數
- isSpikePeriod: true = 該月評論量 > 3倍月均
- maxSimilarity: 與店內其他評論最高 3-gram Jaccard 相似度 (0-1)
- similarCount: 相似度 ≥ 門檻的評論則數
- hotTermCount: 命中全店五星高頻詞組數
- hotTermMaxRatio: 最高頻詞組的出現占比 (0-1)
- nearbyLongReviewCount: 前後 30 分鐘內其他長評 (>50字) 則數

# IAD 評分量表 (1-5)

## I — incentiveIntensity（利益誘因）
| 分數 | 條件 | 範例 |
|------|------|------|
| 5 | 明文提及打卡送禮/五星送飲料 | 「打卡送奶酪！」 |
| 3 | 提及優惠但非條件交換 | 「開學季好像有加大」 |
| 2 | 順帶提到促銷，不影響評價動機 | 「還有送一小杯涼茶」 |
| 1 | 無任何利益交換跡象 | 大多數評論 |

## A — sentimentAuthenticity（情感自然度）
| 分數 | 條件 | 範例 |
|------|------|------|
| 5 | 有情緒起伏、個人故事、正負兼述 | 「排了半小時但值得，湯真的太香了」 |
| 4 | 語氣自然、有個人感受 | 「老闆很親切，吃起來很舒服」 |
| 3 | 平鋪直敘，無明顯真假傾向 | 「湯頭不錯，份量大」 |
| 2 | 公式化堆疊形容詞 | 「環境優美服務親切餐點美味」 |
| 1 | 機器人/罐頭感、完全無情感 | 「推薦」「讚」 |
⚠️ 短≠低分。「飯糰很爽」語氣自然→A=4。「服務好東西好吃」堆疊→A=2。判斷依據是語氣，不是長度。

## D — descriptionGranularity（描述細緻度）
| 分數 | 條件 | 範例 |
|------|------|------|
| 5 | 具體品項+口感/體驗細節 | 「豚骨拉麵麵硬湯濃，叉燒有火烤香」 |
| 4 | 提及品項+簡短評價 | 「嫩煎雞胸餐好吃，出餐快」 |
| 3 | 提及具體對象（餐點名/人物/場景） | 「蘿蔔糕好吃」「老闆親切」 |
| 2 | 僅類別描述，無具體對象 | 「餐點美味，環境乾淨」 |
| 1 | 空洞萬用套話 | 「好吃讚」「CP值高」「推薦」 |
⚠️ 有具體名詞（餐點名/人名）→ D≥3，不因為短就降分。

# 判定規則（依序檢查，符合任一 → isWashed: true）

規則1【利益交換】
  IF I≥3 AND D≤2 → isWashed=true, issueType="incentive"
  IF 明文提及「打卡/送禮/五星送X」 → isWashed=true, issueType="incentive"
  例外: IF D≥4 AND A≥4 → 即使提及優惠也不判洗評（有真實消費細節）

規則2【空洞模板】
  IF D≤2 AND A≤2 → isWashed=true, issueType="template"
  IF isSpikePeriod=true AND D≤2 → isWashed=true, issueType="template"

規則3【情感虛假】
  IF A≤1 AND D≤2 → isWashed=true, issueType="template"

規則4【結構同質】— 僅看數值欄位，與評論文字內容無關
  IF maxSimilarity≥0.55 AND similarCount≥2 → isWashed=true, issueType="template", verdictBasis="structural"
  IF hotTermCount≥2 AND hotTermMaxRatio≥0.3 → isWashed=true, issueType="template", verdictBasis="structural"
  ⚠️ similarCount=1 或 maxSimilarity<0.55 不觸發此規則。寫入 reasoningPath 作輔助訊號。

以上皆不符合 → isWashed=false, issueType="none"
